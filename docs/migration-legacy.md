# 历史版本源码获取迁移

2026-11-04 将 18.06、19.07、21.02 三个入口迁移到共享的 Git 获取器。GitHub 已停止提供 SVN 接口，旧脚本里的 `svn co`、`svn export` 不能继续使用；缺失的 `mvdir` 等辅助命令、失效仓库和变化的子目录也需要一并处理。

统计包含原脚本实际执行的 Git、SVN 和 wget 获取命令，不包含注释。21.02 的 196 条由 195 条 Git 获取和 1 条 `Parted.Makefile` 下载组成。重复调用也保留覆盖记录，因此命令数不等于仓库数、源码目录数或最终安装包数。

原脚本保存在 [tests/fixtures](../tests/fixtures/) 的 `legacy-packages-*.sh.txt`，仅作为回归检查基线，不再用于执行更新。测试逐行核对获取命令与覆盖表，并检查每项映射都能找到对应来源。

## 为什么不能只使用最新发布快照

旧脚本会先清空目标分支的工作目录，下载失败后仍以成功状态退出。核查发现，2025 年的 18.06 最新输出只剩 Argon 配置和 parted 等少量内容，19.07 输出也已丢失大量 SVN 来源。把这些残缺输出当作唯一兜底会延续包丢失。

迁移保留可获取的上游来源，同时回溯对应发布分支中较完整的历史提交，按需要恢复已消失的主题、插件和集合来源：

| 版本 | 固定提交 | 用途 |
| --- | --- | --- |
| 18.06 | `37da719c3be3478d956fc899fd91903216bd7a0c` | 2023-08-18 的已发布源码，包含 61 个可识别的 OpenWrt 候选配方 |
| 18.06 | `c1cd1daaee398559574a102c075698122755aac4` | 2021-03-23 的较完整输出，包含 91 个候选，补全后来消失的内容 |
| 19.07 | `c382fcbdb77353e642f6d41ed99fe32adc048494` | 2023-08-18 的已发布源码，包含 412 个候选 |
| 19.07 | `3080bd71accd03a5a0c950a7e0edf7df9b95e1d2` | 2022-02-13 的较完整输出，包含 404 个候选，补全旧主题及 Bypass 等内容 |
| 21.02 | `c0ce1126afe2576f28ad720a9840ea3ff5c43b6b` | 2025-05-15 的完整历史输出，作为部分冻结来源及最终补全来源 |

18.06、19.07 的四份快照已逐候选核对，全部能在生成报告中找到导入或重复来源处置。候选统计按包目录识别，并合并已由父目录包含的嵌套配方；不同快照之间有重叠，不能把这些数字相加当作最终包数。

固定快照只能保留当时已经发布的源码，不能恢复不可达上游中从未发布的内容。快照不是替代全部更新：仍有效的独立仓库及合适分支继续通过 Git 获取，旧源码用于明确的兼容选择和缺失补全。

## 按旧版本选择来源

- 18.06 的 Argon 主题和配置使用各自的 `18.06` 分支，Edge 保留 `18.06`，wrtbwmon 及其界面保留 `old-master`，不使用面向新 LuCI 的默认分支替代它们。
- 19.07 的 Argon 主题与独立配置固定为同一历史输出中的配套组合；官方 LuCI、packages 来源选择 `openwrt-19.07`。ImmortalWrt 当前没有同名 19.07 分支，仍需使用其历史 18.06 或原有 21.02 配方的条目已在覆盖表注明，不能据此承诺原生 19.07 兼容。
- 三个旧版本的 `fw876/helloworld` 使用 `master`。该分支保留面向旧版本的说明及旧包选项，但上游仍要求为 OpenWrt 21.02 及更早版本升级 Go 工具链后才能编译 Xray 等组件。
- 21.02 使用 Argon `v2.3.2` 搭配历史独立配置插件、Lienol 的 `lua` 分支，以及来源清单中核实过的旧 ref。已改为 ucode 的部分默认分支保留历史 Lua 实现。原 HomeProxy 源码虽被保留，其 firewall4 依赖仍需额外回移植。

21.02 的部分未分版本集合源采用 `frozen-aggregate`：由固定的 2025-05-15 已发布合集保留当时功能，不把集合仓库当前 HEAD 新增的 25.12 专用内容直接混入旧分支。独立包冻结、维护仓库替代和重命名均在覆盖表逐行说明。

19.07 的 `fhh200000/luci-theme-lafite-port` 是没有 OpenWrt Makefile 的安装树。生成器以 `archive` 模式完整保留源码，并在 `MIGRATION.tsv` 记录 `preserved`；它不计入可识别的软件包目录，也不被描述成已经可编译的 LuCI 包。

21.02 的历史 `luci-app-rtorrent` 使用自行生成 IPK 的 Makefile，不是标准 OpenWrt 配方；它同样按 `archive` 保留完整源码。25.12 的本地 rTorrent 包装不会自动套到旧版。原 DNSPod 独立脚本、服务定义和许可证通过单文件导入保留，也不计作新的标准包配方。

## 获取失败与版本补丁的边界

[共享获取器](../scripts/generate-packages.sh) 支持包目录、集合树、套件、单文件和源码归档。原来的 `Parted.Makefile`、`luci.mk` 等下载改为从记录了 commit 的 Git 来源复制，保留原单文件用途。

生成只接受空输出目录，先在临时目录完成获取与整理。网络失败、指定 ref 不存在、包目录或必需文件缺失都会终止任务，工作流不得发布该次结果；没有忽略错误后继续发布的处理。同名包去重、固定历史补全和明确归档属于清单中的处理，均需留下记录，不能作为静默跳过失败来源的理由。

各版本共用来源记录、路径检查和迁移后的 LuCI/Go helper 路径修正。25.12 专用的 Qt5、po2lmo、geodata 等依赖改写及本地包装模板只在 25.12 入口启用，不自动施加到旧版源码。旧脚本原有的基础系统包排除规则继续留在迁移报告中。

每次生成附带 `SOURCES.lock`、`PACKAGES.tsv` 和 `MIGRATION.tsv`，分别记录实际 commit、包归属及检查标签、逐项处置。最终来源与包目录数量应以对应版本的成功运行报告为准，不能沿用调整分支前的中间结果。

2026-11-04 对三版均完成实际 Git 获取和完整生成；最终结果如下，归档源码与根目录辅助文件不计入包目录数：

| `packages-21.02.sh` | 155 | 523 | rTorrent 手工 IPK 构建树、DNSPod 独立脚本 |

各版首次验证使用真实网络读取上游。最后的分支选择和去重顺序调整复用已验证的 Git 对象并获取缺失来源，完整生成均返回成功；没有使用成功占位目录或忽略错误来绕过下载失败。18.06、19.07 的四份历史快照候选均有处置记录，21.02 的 575 处历史配方也按实际配方身份、目录包含关系逐项核对。

三套离线回归共 25 组检查通过，覆盖全部入口、版本隔离、原下载命令逐行覆盖、归档和单文件保留、Xray 子包命名、错误传播、空目录保护及发布流程；ShellCheck 和 Actionlint 通过。工作流现在先运行这些检查，再生成和发布。

发布暂存使用 `git add --all --force`，确保上游已经跟踪、但又被其 `.gitignore` 匹配的源码仍被完整提交。实测旧方式会漏掉 PushBot 运行时必需的 `package_manager.sh` 等文件。这里的强制选项只作用于本地暂存；远端仍使用普通推送，发生并发更新时会拒绝覆盖。

全量生成成功说明来源可获取且已按清单整理，不等于全量编译、依赖兼容或所有架构运行通过。历史标签和当前分支都需要结合实际固件源码验证；本次迁移不会把仅保留源码的包表述为已完成移植，也不会把 25.12 SDK 的验证结果套用到三个旧版本。
